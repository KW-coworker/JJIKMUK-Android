# 스캔 결과 목록 직접 표시 연결

2026-11-09. develop 기준 추가 기능. 기본 OFF이며 기존 스캔·수동 검색·상세·가족 선택 흐름을 유지한다.

## 사용자에게 보이는 변화 (켜진 새 APK만)

사진 한 번 → `POST /api/product-scans` → 서버가 정렬한 상품 목록을 그대로 표시한다. 검색창에는 자동 검색어를 넣지 않는다. 직접 입력하고 검색하면 기존 상품 검색 API를 호출한다. 상세 진입에는 기존 barcode 문자열을 그대로 사용한다. 개인 적합성 판정은 이 스캔 목록의 책임이 아니다.

빈 근거 결과는 기존 재촬영/직접 검색 안내로 연결한다. 기술 오류를 빈 정상 목록으로 바꾸거나, 기존 OCR로 자동 우회하거나, 사진/GPT 요청을 자동 재전송하지 않는다. 취소·직접 검색 뒤 늦게 도착한 결과가 화면을 덮어쓰지 않는다.

## 검토할 변경

- ScannerListService와 인증/HTTP/parser를 추가하고 기존 ScannerAnalysisController에 선택적 서비스 연결.
- PreparedScannerPhoto에 촬영별 UUID를 추가. 같은 사진을 재전송하는 경우 같은 번호 유지.
- JWT는 기존 AuthorizedOperations를 사용한다. 전송 전 갱신은 허용하지만 HTTP 실패 후 사진 자동 재전송은 하지 않는다.
- 기존 Base URL 그대로 사용. 기존 `/api/ocr`, 상품 검색·상세 API와 DTO를 삭제하지 않는다.
- 빈 검색어일 때 결과 제목에 빈 따옴표를 표시하지 않도록 조정.
- Google Web Client ID·서명·회원가입·로그인 설정은 변경하지 않는다.

## 활성화와 복귀

기본 빌드는 기존 흐름이다. 서버의 새 계약 활성화와 별도 시험 승인이 끝난 뒤:

```powershell
.\gradlew.bat :app:assembleDebug '-Pjjikmuk.scanListEnabled=true'
```

기존 흐름으로 돌아가려면 옵션 없이 빌드한다. 기존 APK에도 새 서버 목록 기능이 자동 적용되는 것은 아니다. API/인덱스가 준비되기 전 기능 ON APK를 팀원에게 운영 테스트용으로 배포하지 않는다.

서버는 기본적으로 유료 사진 재시도를 끄고 있으며 앱은 이를 강제할 파라미터를 보내지 않는다. 사진 외부 전송 활성화는 별도 운영 승인·동의 정책 대상이다.

## 계약·검증

함께 제공한 `product-scans-v1.md`에 요청·응답·오류·nullable 필드·버전·설정 예시가 있다. 상세 barcode와 productId를 혼동하지 않는다. 응답 순서와 requestId를 보존한다.

- 전체 단위 검사 358 PASS, 실패/skip 0. 기능 ON debug APK 빌드 성공.
- lintDebug 통과(새 이슈 0). 기존 baseline이 숨기는 4 errors/75 warnings/2 hints는 이번에 고친 것이 아니다.
- 실제 Python→Kotlin 생성 응답을 Android HTTP/파서 fixture로 검증했다. fixture는 가상 상품이며 민감정보가 없다.
- 서버 순위·빈 검색창·직접 검색·중복 촬영·늦은 결과·401/403·429·리다이렉트·오류 자동 재시도 금지 검사.
- 실제 카메라/휴대폰/AWS/RDS/GPT 요청은 이번 검사에 포함되지 않는다.
- Google OAuth 자체는 별도 등록/기기 검증 대상이다.

담당자 수락 기준: 기본 OFF에서 기존 스캔 유지, ON에서 목록 순서/상세/직접 검색/재촬영 확인, 로그아웃·취소 후 늦은 결과 미표시. 서버가 아직 새 계약을 제공하지 않으면 기능은 켜지 않는다.
