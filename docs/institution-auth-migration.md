## 현재 구현

사용자 제공 TEAM_DELIVERY(2026-10-29)에 따라 공통 Base URL을 `https://43.203.42.36/`로 변경했다. 기존 Tailscale 주소·OCR 팀 토큰 설정을 앱에서 읽거나 주입하지 않는다. debug/release 모두 같은 서버를 사용하며 HTTPS 검증을 유지한다. DB는 기존 데이터를 이전했으므로 회원·상품을 다시 등록할 필요가 없다.

| 항목 | 반영 내용 |
| --- | --- |
| 로그인·상품·챗봇·OCR | 공통 기관 HTTPS 주소 |
| OCR | POST /api/ocr, multipart image, Authorization: Bearer 로그인 Access Token |
| 처리 요청의 401 | 현재 요청의 세션만 무효화하고 재로그인 안내. 전송 후 토큰 갱신 및 요청 재전송 없음 |
| 전송 전 만료 | 기존 세션 갱신 정책으로 확인한 뒤 전송. 갱신 결과 불명 시 재로그인 |

로그인 비밀번호 불일치를 포함한 모든 401을 일괄 로그아웃으로 처리하지 않는다. 이전 계정 또는 이전 토큰의 늦은 응답이 새 세션을 삭제하지 않는다. OCR·챗봇 등 전송된 처리 요청은 네트워크 오류, 408/503 및 리다이렉트에서도 자동 반복하지 않는다.

## 가입 사진 정책과 동작

**사용자 확정: 같은 계정은 다른 기기에서도 서버 사진 복원, 다른 계정끼리는 분리.** 가입 중 사진 선택을 허용하고 최종 가입 제출 직전에 앱 전용 noBackupFilesDir에 임시 JPEG를 저장한다. 제출 전 입력 화면만 종료한 경우까지 영속 저장하는 것은 아니다.

1. 가입 성공 userId와 정규화한 이메일로 임시 사진을 연결한다. 서버 가입 응답은 자동 로그인용 토큰이 아니므로 사진 업로드는 로그인 후 수행한다.
2. 해당 계정 로그인 후 서버 사진을 먼저 조회하고, 사용자가 선택한 사진을 저장할지 확인한다. 다른 기기에서 저장된 사진을 자동 덮어쓰지 않는다.
3. 저장 성공하면 임시 파일만 정리한다. ‘나중에 설정하기’는 임시 파일을 유지하며 다음 로그인에 다시 확인한다. ‘임시 사진 삭제하고 계속’은 서버 사진을 삭제하지 않는다.
4. 업로드 응답 유실 시 자동 재전송하지 않고 서버 사진부터 재조회한다. 다른 계정으로 전환하면 이전 계정 사진을 표시하거나 업로드하지 않는다.
5. 임시 사진은 앱 삭제/데이터 초기화 시 사라지지만 서버에 저장된 사진은 같은 계정으로 복원한다. 임시 파일은 성공·명시적 삭제 전까지 보관한다.

기존 인증 v2에 사진 조회·업로드·삭제 API가 있으므로 새로운 사진 API를 중복 요청할 필요는 없다. 실제 계정의 업로드와 두 기기 복원 검증은 남아 있다. 서버의 현 제한에 맞춰 JPEG/PNG 및 2MiB 이하로 변환하며, 장기 저장소·제한 정책의 최종 협의는 별도다.

## 비밀번호

사용자 승인으로 새 비밀번호는 영문·숫자 필수, 특수문자 선택, ASCII 8~72자로 통일했다. 한글·공백·이모지·악센트 문자는 허용하지 않는다. 안내 문구만 변경하고 기존 비밀번호 화면 위치·색상은 유지했다. 기존 계정 로그인에는 새 생성 규칙을 강제하지 않는다.

## 담당 구분과 남은 작업

로그인·회원가입을 먼저 마무리한다. MyPage·상품스캐너 추가 기능은 별도 후속이다. 서버 이전의 공통 주소/인증과 OCR JWT 전환만 이번 범위에 포함했다.

- **인증 다음 단계:** OAuth Web Client ID, Android 패키지/서명 등록, SMTP/테스트 계정 확보 → 실제 가입/로그인/갱신/프로필 완료/사진 복원 검증 → 오류 UI 검토.
- **백엔드 확인:** Refresh가 소비되지 않았음을 보장하는 오류별 재시도 조건, Access 만료 상태에서 서버 세션을 폐기할 로그아웃 절차, Google 미완료 계정의 허용 경로/오류 코드, OTP 타이머 우선순위·시계 오차.
- **MyPage 후속:** 가족 CRUD 화면, 관계/이모지 계약, 기존 로컬 데이터 이전, 계정별 대상 선택과 전체 해제 none 검증. 로그인·회원가입에 가족 편집 화면을 추가하지 않는다.
- **스캐너 후속:** 실제 JWT OCR, 검색·상세 연결과 비교스캔, 분석 대상 계약, 결과 오류/샘플 분리 검증.
- **다른 담당자:** 챗봇 answer/sources/product_candidates, 후보 선택 시 barcode+원래 질문 재전송, 상품 상세에서 barcode 전달, 사용자 동의 UI와 externalAiConsent 연결. 공통 통신 수정만으로 챗봇 전체 연동이 끝난 것은 아니다.
- **상품 담당자:** GET /api/products/{barcode}/variants 연결 여부 결정.

TEAM_DELIVERY의 1번은 공통 주소와 본인 담당 OCR에 적용했고, 5번은 공통 인증 정책으로 반영했다. 챗봇 화면의 안내·동의/후보 처리는 챗봇 담당자와 맞춰야 한다. 문서는 전달 초안이며 외부 메시지는 보내지 않았다.
