# 로그인·회원가입 화면 흐름

> 실제 Route는 `feature/auth/navigation/AuthRoute.kt`, 연결은 `AuthNavHost.kt`가 기준이다. 미입력/입력 중/오류는 별도 화면이 아니라 같은 화면의 상태다. API 요청/복구 구현은 [구현현황](구현현황.md)을 참조한다.

## 앱 시작과 로그인

| 시작/이벤트 | 다음 흐름 |
| --- | --- |
| Splash, 저장 세션 없음 | PermissionApproval → AuthChoice |
| Splash, 저장 세션 있음 | SessionEntry에서 본인 정보 확인 |
| AuthChoice | 로그인 또는 회원가입 선택 |
| Login 성공 | SessionEntry → GET me 결과로 분기 |
| SessionEntry, 로그아웃 상태 | AuthChoice |
| SessionEntry, 프로필 미완료 | ProfileCompletion |
| SessionEntry, 조회 실패 | 세션 유지·재시도/로그아웃 선택 |
| SessionEntry, 완료 | 해당 계정의 가입 임시 사진 확인이 필요하면 확인 → Home |

이메일 형식만 맞으면 로그인 성공으로 간주하는 과거 임시 정책은 폐기했다. debug 개발용 홈 진입은 실제 로그인과 별도이며 서버 인증 성공 검증에 사용하지 않는다.

## 일반 회원가입

`SignUpEmail → SignUpOtp → SignUpPassword → SignUpNickname → SignUpConditions → 필요한 세부 조건 → SignUpProfile → 실제 signup 성공 → SignUpComplete → Login`

- 이메일 발송 성공에만 OTP로 이동한다. 코드/증명 만료·재전송 제한은 서버 결과와 상태에 따른다. 하드코딩된 정답 OTP는 없다.
- 닉네임 사전 확인은 예약이 아니다. 최종 제출 중복 시 다른 입력은 유지하고 닉네임을 수정한다.
- 채식 선택 시 SignUpVegetarian, 알레르기 선택 시 SignUpAllergies를 사용한다. 조건 없음도 허용한다.
- 사진은 최종 가입 제출 때 임시 보관하며 로그인 후 계정 확인·서버 저장을 진행한다. 가입 응답만으로 홈에 들어가지 않는다.
- 완료·로그인 이동 후 뒤로가기로 소비된 OTP/가입 제출 화면을 재사용하지 않는다. 결과 유실은 재전송 대신 안내된 복구 흐름으로 이동한다.

## 비밀번호 찾기

`PasswordResetEmail → PasswordResetOtp → PasswordResetNewPassword → 실제 재설정 성공 → PasswordResetComplete → Login`

가입 증명과 재설정 증명을 혼용하지 않는다. OTP 검증 후 새 비밀번호 화면에서는 이전 OTP 화면으로 돌아가 반복 사용하지 않는다. 새 비밀번호 화면에서 되돌아가면 이메일 재인증을 시작한다. 실패/결과 불명 처리는 [구현현황](구현현황.md)의 복구 규칙을 따른다.

## Google 로그인·추가 입력

Login의 Google 버튼 → GoogleLogin에서 계정 선택 → 서버 응답에 따라 분기한다.

- 정상 서비스 로그인 → SessionEntry.
- 연결 필요 → 기존 비밀번호 확인/명시적 연결 또는 취소/비밀번호 찾기. 연결 증명으로 홈이나 API에 접근하지 않는다.
- ProfileCompletion은 기존 닉네임·조건·프로필 확인 UI를 재사용한다. 일반 가입 OTP/비밀번호/signup을 반복하지 않는다.
- profile/complete 성공 또는 GET me로 완료 확인 → SessionEntry → Home. 조건 선택 유무만으로 완료를 판단하지 않는다.

## 상태와 범위

화면 재생성 시 ViewModel 입력 상태를 유지하되 계정 전환·흐름 초기화 뒤 늦은 응답은 반영하지 않는다. 일반 비밀번호·OTP·증명은 저장소에 평문 보관하지 않는다. 미완료 계정의 서버 접근 범위는 [통합 협의안](../../협의/로그인-회원가입-백엔드-협의안.md)에서 결정한다.

AccountPassword/AccountWithdrawal은 가입 후 마이페이지 계정 보안 기능이다. 가족 편집 화면은 로그인·회원가입 흐름에 추가하지 않는다.
