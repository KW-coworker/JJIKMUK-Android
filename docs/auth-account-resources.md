# 계정 리소스 API 연결 현황

> **2026-10-31 최신 반영:** 기관 HTTPS·OCR JWT, 가입 사진 임시 보관/같은 계정 서버 복원, ASCII 비밀번호를 구현했다. [최신 구현·검증·남은 작업](institution-auth-migration.md)을 우선한다. 아래 이전 단계의 미구현/설정 안내는 해당 시점 기록이다.

> 2026-10-31 · `feature/auth-contract-models`. 계약은 [백엔드 원문](API/README.md) 기준. 실제 운영 계정·서버를 수정하는 테스트는 하지 않았다.

## 작업 영역 구분

- 로그인·회원가입: 이메일/Google 인증, 미완료 가입자의 본인 추가 입력, 세션·복구 흐름.
- **마이페이지:** 가입 후 본인 정보·알레르기·식이조건 수정, 사진, 계정 보안, 가족 프로필 관리. 사용자가 가족 변경은 마이페이지 영역이라고 명시했다. 로그인·회원가입에 가족 관리 화면을 추가하지 않는다.
- 이번 단계는 마이페이지 본인 식이조건 수정만 연결했다. 가족 프로필 변경은 이번 구현 범위가 아니다.

## 마이페이지 본인 식이조건 수정

- 실제 로그인 → 마이페이지 → 식이 조건 관리에서 본인 GET me를 조회한다. 기존 채식 카드·알레르기/선호 칩·헤더 및 공통 버튼을 재사용한다. 이 경로는 로컬 가족 저장소를 읽거나 수정하지 않는다.
- 서버 카탈로그를 기존 가입 매핑으로 복원/변환한다. 채식 1개와 영양 조건은 `specialDiet` CSV로, 알레르기는 `allergies` CSV로 전송한다. 화면의 한글 이름을 API 코드로 보내지 않는다.
- 변경한 필드만 PATCH한다. 모두 해제하면 해당 필드에 명시적 null, 변경하지 않은 필드는 생략한다. 닉네임·질환·기피 성분·완료 여부는 수정하지 않는다.
- 저장 성공 후 응답과 본인 세션 프로필을 반영하고 완료 안내를 표시한다. 명확한 실패는 선택 유지, 응답 유실/5xx/갱신 후 결과 확인 필요는 편집·재저장을 막고 GET me 재확인만 허용한다.
- 재확인 시 수정한 필드의 선택은 유지하고, 수정하지 않은 필드는 최신 서버 값을 받아들인다. 서버에 이미 같은 값이 저장됐으면 추가 PATCH를 보내지 않는다. 같은 필드를 여러 기기에서 편집할 때는 현재 서버 계약의 마지막 저장 우선 정책이다.
- 모르는 서버 코드 또는 여러 채식 유형은 빈 선택으로 바꾸지 않고 수정을 막는다. 새로운 카탈로그를 지원하기 전까지 사용자 정보를 임의로 지우지 않는다.
- 계정 전환 뒤 이전 초안/응답을 반영하지 않는다. PATCH는 편집을 시작한 세대를 요청 직전·갱신 이후에도 확인한다. 미저장 선택은 ViewModel 메모리에만 유지하며 화면 재생성은 보존, 뒤로가기 시 버리기 확인, 프로세스 종료 후는 서버 조회부터 시작한다.
- debug 개발용 홈은 기존 로컬 화면을 유지한다. 실제 로그인 경로의 가족 선택/수정 UI는 서버 가족 단계에서 별도로 연결한다. 기존 Room 가족 데이터와 예시 데이터는 이번에 이전·삭제하지 않았다. 로그인/회원가입 내비게이션에는 화면을 추가하지 않았다.

## Google 로그인·기존 계정 연결

[설정 및 요청 문서](auth-google-integration.md)에 구현 흐름, 사용자 미확보 설정, 백엔드 전달 초안과 실제 시험 순서를 정리했다. 연결 필요 응답은 세션을 만들지 않으며 명시적 비밀번호 확인 후 성공한 경우만 기존 시작 확인 흐름으로 진입한다. 새 Google 사용자는 추가 프로필 완료 전 홈에 진입하지 못한다.

## 추가 프로필 입력·완료 화면

- 로그인/앱 시작의 GET me 응답이 `profileCompleted=false`이면 추가 입력으로 이동한다. 기존 ‘준비 중’ 안내를 제거했고 완료 전 홈 진입은 계속 차단한다.
- 기존 `SignUpNicknameScreen`, `SignUpConditionsScreen`, `SignUpAllergiesScreen`, `SignUpVegetarianScreen`, `SignUpProfileScreen`을 재사용한다. 별도 ViewModel이 담당하므로 이메일 OTP/비밀번호/일반 signup을 다시 호출하지 않는다.
- 현재 본인 닉네임 유지·대소문자 변경은 공개 중복 API 결과로 막지 않는다. 다른 이름은 사전 중복 확인을 하고, 최종 complete의 중복 오류에서도 닉네임 외 조건을 유지한다. 닉네임 수정 시 기존 확인 상태를 초기화한다.
- 조건을 하나도 선택하지 않아도 완료할 수 있다. 서버 CSV를 기존 UI ID로 복원하고 정규 코드로 전송한다. 전체 제출이므로 화면에서 편집하지 않는 `diseases`/`dislikedIngredients`는 기존 서버 값을 유지한다. 알 수 없는 서버 코드/복수 채식 유형은 조용히 지우지 않고 제출을 막는다.
- 정상 완료 또는 응답 유실 후 GET me에서 완료 확인 → 세션 프로필 반영 → 시작 확인/홈 경로. 완료 응답 유실·손상·5xx·갱신 후 재확인은 재전송 대신 GET me 버튼을 제공한다. 여전히 미완료면 입력을 유지하고 사용자가 확인한 뒤 다시 제출한다. 상태 조회도 실패하면 입력·세션을 유지한다.
- 연타/제출 중 수정·이탈·이전 계정의 응답을 차단한다. AuthProfiles는 Refresh 이후에도 소유 세대를 재확인해 이전 계정 입력을 새 토큰으로 보내지 않는다.
- 같은 ViewModel이 살아 있는 동안 화면 회전·백그라운드 이동은 초안을 유지한다. **미저장 초안은 디스크에 보관하지 않는다.** 프로세스 종료/로그아웃 후에는 GET me의 서버 정보부터 재개한다. 로그아웃 전 입력 손실 안내를 제공한다.
- 이 추가 입력은 닉네임·조건 확인 범위이며 사진은 완료 후 마이페이지 설정 안내를 표시한다. 이메일 가입의 기존 사진 선택/임시 보관 정책 대기는 그대로다.

## 계정 보안 화면 동작

- 마이페이지 → 우상단 설정 → 계정 및 보안 → 비밀번호 변경 또는 회원 탈퇴.
- 비밀번호 변경은 현재 비밀번호·새 비밀번호·확인을 입력한다. 새 비밀번호만 기존 공통 생성 규칙으로 검증한다. Google 전용 계정은 설명을 표시하며 요청하지 않는다.
- `LOGIN_FAILED/field=currentPassword`와 `PASSWORD_INVALID/field=password`를 각각 현재/새 입력란에 표시한다. 명확한 실패는 입력·세션을 유지한다.
- 탈퇴는 기존 동의 UI를 재사용한다. 동의 없이 요청할 수 없고, 기존의 로컬 완료 전환은 제거했다. 처리 중에는 중복 요청·화면 이탈을 막는다. ‘계속 이용하기’는 동의 전후 모두 사용 가능하며 요청 중에만 잠시 비활성화된다.
- 성공 응답 후 현재 세션과 메모리 사진은 정리된다. 홈 밖의 별도 경로에서 완료를 표시하므로 세션 삭제로 완료 화면이 사라지지 않는다. 완료 버튼/시스템 뒤로가기는 인증 화면으로 이동하고 이전 홈·입력 화면 기록을 제거한다.
- 응답 유실/서버 5xx/처리 도중 취소는 성공으로 간주하지 않는다. 재전송을 막고 사용자가 ‘다시 로그인하기’를 선택할 때만 로컬 세션을 정리한다. 단순 네트워크 실패만으로 자동 로그아웃하지 않는다.
- Android 저장 상태에는 처리 종류와 소유 계정 ID만 보관한다. 처리 중 상태가 복원되면 결과 확인 안내를 띄우며 자동으로 재요청하지 않는다. 비밀번호는 저장 상태/디스크/로그에 남기지 않고 화면 이탈·성공 시 비운다. 이 저장 상태는 영구 작업 이력이나 서버 멱등키가 아니다.
- 계정 전환 시 이전 입력·늦은 완료를 새 계정에 적용하지 않는다. Refresh 대기 후에도 요청 직전 세션을 다시 확인한다. 로컬 세션 파일 삭제가 실패하면 메모리 접근은 차단하고 완료 화면에서 저장소 오류를 안내한다.
- 개발용 홈에서 실제 계정 변경·탈퇴는 실행하지 않는다. 화면 모양은 기존 Preview로 검토할 수 있다. 기존 소유자 없는 가족/찜 등 로컬 자료의 이전·삭제 정책은 이번에 임의 결정하지 않았다.

## 사진 화면 동작

마이페이지 → 프로필 수정 → 사진 버튼 → 갤러리에서 선택. 시스템 사진 선택기는 한 장만 받는다. 선택 이미지를 메모리에서 변환한 뒤 서버에 전송하고, 서버가 재인코딩한 사진을 다시 조회해 표시한다. 기본 사진으로 변경할 때는 삭제 확인을 먼저 받는다.

- 서비스 JWT는 고정된 인증 API에만 전달하며 반환 photoUrl을 임의 외부 URL로 따라가지 않는다.
- 사진 바이트는 메모리에서만 관리하고 HTTP·Coil 디스크/메모리 캐시를 사용하지 않는다. 기기에 영구 URI·사진 파일을 남기지 않는다.
- 계정 전환 시 이전 사진을 즉시 숨기고 늦은 응답을 버린다. 이전 계정 요청이 느려도 새 계정 조회를 막지 않는다.
- 사진 없음은 404 PHOTO_NOT_FOUND만 기본 사진으로 처리한다. 통신/권한/다른 404는 기존 사진 유지·재확인 안내다.
- 잘못된 교체 파일은 기존 사진을 유지한다. 저장/삭제 결과가 불명확하면 추가 변경을 막고 서버 사진 재조회 후 다시 진행한다. 네트워크 실패만으로 로그아웃하지 않는다.
- 인증 주소 미설정/개발용 홈 진입은 사진 저장 성공으로 위장하지 않는다. 실제 서비스 세션이 있어야 편집 가능하다.

## API 전송 안전성

모든 추가 변경 API는 자동 재전송하지 않는다. DELETE도 zero-byte one-shot 본문으로 표시해 OkHttp의 503 + Retry-After: 0 후속 전송을 막는다(실제 요청 데이터 없음). 안전한 조회만 기존 AuthenticatedRequests의 갱신 후 1회 재시도 정책을 사용한다. 가족 PATCH의 명시적 null과 version은 보존하며 ownerId/로컬 UUID는 전송하지 않는다.

Google SDK·연결 UI와 계정 보안 화면은 연결했다. 가족 CRUD UI의 오류별 사용자 선택·재조회 절차는 후속이며 가족 HTTP/세션 헬퍼만으로 UI 완료라고 표현하지 않는다. AuthAccountActions 성공은 세션 정리를 담당하지만 가족/찜 등 소유자가 없는 로컬 데이터의 삭제 정책을 대신 결정하지 않는다.

## 검증

단위 테스트 **232개/실패 0**, New_Device 화면 테스트 **26개/실패 0**(기존 인증·보안 14, 추가 프로필 4, Google 연결 4, 본인 조건 4), debug APK 및 release Kotlin 컴파일 성공. 본인 조건 테스트는 변경 필드 생략/null 해제/정규 코드, 모르는 조건 차단, 응답 유실 후 GET 확인·부분 초안 보존, 계정 전환, 연타, 화면 재생성·이탈 확인을 검증했다. 실제 인증/조건 서버는 호출하지 않았다. 이전 사진 처리 테스트 4개 통과 이력은 별도다. 실제 서버·SMTP·Google·두 기기 검증은 후속이다.

## 다음 단계부터 남은 API 작업

1. **로그인·회원가입 후속:** Google Web Client ID/Android 등록 정보를 받으면 [실제 Google 인증·연결 시험](auth-google-integration.md), 실제 OTP/가입·세션 검증을 진행한다. SDK·연결 UI와 마이페이지 본인 조건 수정 구현은 완료.
2. **마이페이지 별도 후속 — 서버 가족 관리:** 가족 CRUD·version 충돌·실제 ‘나’·선택 상태 연결. 관계/이모지 및 기존 소유자 없는 데이터 이전은 합의 필요. 로그인·회원가입에 가족 화면을 추가하지 않는다.
3. **가입 전 선택 사진:** 임시 보관/첫 로그인 업로드 정책 확정 및 구현. 마이페이지 사진 업로드는 완료.

5. **실제 환경 검증·최종 UI:** 배포 커밋/DB/SMTP/Google 설정 확인, 실제 OTP·가입·로그인·사진·변경/탈퇴·두 기기 회귀. 최종 오류 디자인과 백엔드 미답변 정책 확인.
